# Техническое задание: доработка учебного проекта «Python public-key cryptography example»

## 1. Контекст

Репозиторий `python-asymmetric-cryptography` — учебный, наглядный пример асимметричного
шифрования с открытым ключом на Python (упрощённая идея RSA). Текущее состояние:
два файла — `main.py` (весь код) и короткий `README.md`; тестов и лицензии нет.

Главная ценность проекта — **прозрачный, читаемый код без лишних библиотек и «фишек»**.
Шифрование выполняется вручную реализованными примитивами; из встроенного Python
разрешены только базовые операторы (целочисленное деление, взятие остатка, возведение
в степень, битовые операции).

Цель работ: сохранить наглядность, **исправить математические ошибки**, вынести
математику в отдельный модуль, добавить тесты, привести комментарии к английскому
языку, расширить README, добавить лицензию и сделать демонстрацию воспроизводимой.

Все требования ниже — обязательны и должны быть реализованы без нарушения «учебной
прозрачности» кода.

### 2.1. `crypto_math.py` — наглядная математика

Модуль содержит **только чистые функции-примитивы**, без ввода-вывода, без обращения
к `os.urandom`/`random`, без побочных эффектов и без вызова `print`. Ни одна функция не
имеет права читать файлы, время или генераторы случайных чисел.

В модуль переезжают и должны оставаться импортируемыми:

- `mod_exp(x, y, z)` — модульное возведение в степень (повторное возведение в квадрат);
- `bin_sqrt(x)` — целочисленный квадратный корень (floored) бинарным поиском;
- `gcd(x, y)` — НОД по Евклиду;
- `extended_gcd(a, b)` — расширенный Евклид; возвращает `(g, x, y)`, где `a*x + b*y = g`;
- `mod_mul_inverse(a, b)` — модульная мультипликативная обратная;
- `trial_division(x)` — проверка простоты перебором делителей;
- `fermat_test(n, k)` — вероятностный тест простоты Ферма.

Комментарии и докстринги в этом модуле — на английском языке.

### 2.2. `main.py` — запуск и демонстрация

Отвечает только за сценарий, импортируя математику:

```python
from crypto_math import mod_exp, bin_sqrt, gcd, extended_gcd, mod_mul_inverse, trial_division, fermat_test
```

В `main.py` остаются:

- `get_rand(b)` — генерация случайного числа из `os.urandom`;
- `gen_prime(...)` — генерация простого числа;
- `show_stat(...)` — индикатор прогресса (см. п. 4.3);
- кодирование строки в `int` (см. п. 4.4);
- сама схема: выбор/генерация `p`, `q` → `N`, `λ` → `E`, `D` → шифрование/дешифрование;
- «красивый», аккуратный вывод результатов (см. п. 4.3);
- точка входа.

## 3. Исправления математики (критично)

### 3.1. Исправить `trial_division` — пропуск верхней границы

**Проблема.** В текущем коде диапазон делителей строится как `range(3, bin_sqrt(x), 2)`,
верхняя граница не включается. Поэтому делитель, равный `sqrt(x)`, не проверяется и
полные квадраты объявляются простыми. Фактическая проверка на текущем коде:
`trial_division(9) == True`, `trial_division(15) == True`, `trial_division(25) == True`.
Это приводит к генерации составных «простых» чисел и к неверным `N`, `λ`, `D`, из-за
чего дешифрование в общем случае ломается.

**Требование.** Верхняя граница диапазона должна включать `sqrt(x)`:

```python
l = range(3, bin_sqrt(x) + 1, 2)
```

Помимо правки, **добавить поясняющий комментарий**: почему в границу входит `sqrt(x)`
(делитель, равный корню, обязателен для проверки полных квадратов) и почему шаг равен 2.

Также рекомендуется проверку чётности перенести до построения диапазона, чтобы не
создавать диапазон впустую.

### 3.2. Исправить `bin_sqrt(0)` — падение с `UnboundLocalError`

**Проблема.** При `x == 0` цикл не выполняется, и `return r` обращается к неинициализированной
переменной. Проверено: `bin_sqrt(0)` → `UnboundLocalError`. Это же ломает `trial_division(0)`.

**Требование.** Инициализировать `r = 0` перед циклом. Результат должен совпадать с
`math.isqrt`: `bin_sqrt(0) == 0`.

### 3.3. Добавить валидацию открытой экспоненты `E`

**Проблема.** `D = mod_mul_inverse(E, M)` молча возвращает некорректное значение, если
`gcd(E, M) != 1`. При малых простых (`gen_prime(6)`) модуль `M` может быть меньше `65537`
или иметь с ним общий делитель — тогда RSA математически неверен, а код ничего не сообщает.

**Требование.** Перед вычислением `D` явно проверять:
- `1 < E < M` (или как минимум `E < M` для малых демонстрационных параметров);
- `gcd(E, M) == 1`.

При невыполнении — либо подбирать другое `E`, либо завершаться с **понятной явной
ошибкой** (без молчаливого продолжения). Это одна из требуемых «явных ошибок».

### 3.4. Исправить неверные комментарии, искажающие математику

- Строка с `if y % 2:` сопровождается комментарием «если чётно (y & 1)». Условие истинно,
  когда `y` **нечётно** (младший бит равен 1). Комментарий исправить.
- Комментарий к открытой экспоненте утверждает «число Ферма `F(4) = 2 ** 16`». Фактически
  `F(4) = 2**(2**4) + 1 = 65537`, то есть `2 ** 16 + 1`, а не `2 ** 16` (65536). Исправить.

## 4. Схема, вывод и демонстрация

### 4.1. Сохранить схему, но задокументировать приём `p = N − 1`

Саму схему шифрования **менять не нужно**: она наглядна и даёт верный результат `d`.
Однако старший блок кодируется значением `p = N − 1`, а `(N − 1)^E mod N = N − 1` для
любого нечётного `E`. Поэтому `p_enc` всегда равно `N − 1`, то есть старшая часть
сообщения фактически не шифруется, и корректность формулы восстановления
`d = (p_dec + 1) * n + r_dec` держится только на `p_dec == N − 1`.

**Требование.** Явно описать это свойство как **учебный приём** в комментарии в коде
и/или в README. Не маскировать и не «чинить» скрытно.

### 4.2. Зафиксировать ограничение теста Ферма

Добавить короткий комментарий (в `crypto_math.py` и/или README) о том, что `fermat_test` —
**вероятностный** тест и может принять составное число Кармайкла за простое; безопасный
(детерминированный) путь для демонстрации — `trial_division`. Новые алгоритмы при этом
не добавлять.

### 4.3. Аккуратный вывод и индикатор прогресса

- `show_stat` оставить как наглядно-отладочную функцию, но привести в порядок: включить

  исходное сообщение, блоки (`n`, `r`, `p`), зашифрованные значения, расшифрованные
